Information stored on your device

The game does not create an account. Progress stays in local storage on the device you are playing on. Nothing in this build uploads that save to a server we operate.

  • mwfarms_save_v1 — farm progress, settings, an anonymous support id, discovered strains, and similar gameplay data.
  • mwfarms_age_ok — that you confirmed you are 18 or older.
  • mwfarms_ad_consent_v1 — whether you allowed personalized ads or chose non-personalized ads only.
  • mwfarms_entitlements_v1 and mwfarms_pending_purchase_v1 — which test or store purchases this device has already granted, and a pending web checkout if you started one.
  • mwfarms_leaderboard_v1 — your own high scores for the on-device leaderboard. Computer rivals on that board are fictional and are not other players.

Game updates keep that save on this site. They do not delete it when the version changes. Settings can export a backup code or file and import it later. Import asks before it replaces the farm on this device. Store purchases stay on the device and are not inside the backup file.

Clearing site data, or using Reset farm in Settings, removes the save on this device. Reset keeps the local record of store purchases so a restore can apply them again.

Ads

Rewarded ads are optional. Watching one to the end can grant gems or double offline earnings. You can play without watching ads.

The shipped default is test mode. The "ad" is drawn inside the game. It does not contact an ad network, and it does not read an advertising identifier.

If a store build later turns on AdMob or AppLovin, the native ad plugin receives your choice:

  • Personalized — the plugin may use the platform advertising identifier to tailor the ad. This stays off until you tap Allow personalized ads.
  • Non-personalized — the plugin is asked for a non-personalized ad (npa). The game does not request a personalized ad.

The first-launch prompt asks for this choice before any ad can play. You can change it later in Settings. Ad unit ids in this repository are empty until the operator fills them in.

This build does not use the IAB TCF consent-management platform. If you turn on AdMob for the EU or UK, serve a Google UMP (or equivalent) message as well and keep this prompt in agreement with it.

Payments

The default mode is test mode. Tapping a price shows a test confirmation and grants the item on this device. No card is charged and no payment data is sent.

When real payments are turned on:

  • iOS and Android use Apple In-App Purchase or Google Play Billing. The game sends the receipt or purchase token, and the product id, to the receipt verifier at [VERIFY ENDPOINT]. The item is granted only if that server answers that the receipt is paid for that product. Card numbers are not collected by the game.
  • The website may use Stripe Checkout. Card details are entered on Stripe's page, not in the game. After payment, the game sends the Checkout session id to the same verifier and grants the item only if the server confirms it. Stripe is not offered inside the iOS or Android apps.

Until [VERIFY ENDPOINT] is configured, real-money purchases are not granted.

Analytics

This build does not include an analytics SDK, an advertising-measurement SDK, or a crash reporter. Gameplay events are not sent to an analytics service. Leaderboard scores stay on the device unless a native Game Center or Play Games provider is connected later. If that changes, this policy has to be updated before the new build ships.

Children

The game is for players 18 and older. It is not directed at children, and it should not be listed in a kids category or a Designed for Families program.
